# Discover the deployment environment

This portable package intentionally contains no account-specific topology. Obtain the intended instance and target from the application's checked-in binding, authorized local CLI configuration or a permission-controlled operations source. Historical examples do not establish current availability or authorization.

Verify context, Coolify panel URL, project, environment, application/target, destination, configured Git repository/branch, runtime port, health check and persistent storage. Use `coolship config show`, `coolship doctor` and `coolship status`, subject to installed help. Do not silently switch servers after a failure.

`COOLSHIP_URL` is the Coolify panel root, without `/api/v1`. Use `COOLSHIP_TOKEN` from a protected secret store; never commit it. Inspect environment variable names without showing their values.

Coolify domain settings, DNS, Cloudflare Tunnel, Access policy, TLS and application listening ports are distinct layers. Private services may intentionally lack public hostnames. Host/Proxmox administration requires a separate task and access scope.

Keep resource UUIDs generated by link/init; do not reuse another application's binding. Check backups and rollback limits before stateful changes. See [CLI reference](commands.md) for command/version constraints.
