# Plan feature

Inspect project instructions, existing behavior, relevant code and tests before proposing changes. Separate explicit requirements from assumptions; ask only about decisions that change scope or architecture.

Identify affected interfaces, data flows, compatibility constraints and existing patterns. Compare alternatives only where there is a meaningful tradeoff. Prefer the smallest design that meets the requirements.

Produce a plan with the intended behavior, affected files or components, ordered implementation steps, acceptance checks and material risks. Include migration and rollout steps when data or compatibility changes require them. Mark unresolved decisions and dependencies. Do not implement or deploy merely because planning was requested.
