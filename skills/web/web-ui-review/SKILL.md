# Web ui review

Identify the audience, critical tasks and available pages. Inspect rendered behavior where tools permit, plus markup and styles. State viewport/browser and any limits when only source is available.

Check keyboard navigation, focus visibility/order, semantic controls, accessible names, form labels and errors, contrast, zoom/reflow and reduced motion. Exercise loading, empty, error and success states. Check narrow and wide layouts, long content and touch interactions. Use the applicable accessibility standard as a reference when judging conformance; automated checks alone do not establish it.

Prioritize findings by user impact. Provide location, reproduction, affected task and a specific remedy. Distinguish observed failures from untested concerns. Modify the UI only when requested and verify the affected flows afterward.
